#ISMS-01
★★★★★
資訊安全管理系統 (ISMS) 的定義、目的與重要性
核心概念
理解 ISMS 是一個框架與過程，用於建立、實施、運作、監控、審查、維護和改進組織的資訊安全。其主要目的是透過風險管理來保護資訊資產，確保組織的業務持續性，並符合法規和合約要求。其重要性在於能系統化、持續性地提升組織的資安防護能力。 對應能力：資訊安全管理概論 K09, K10, K11, K12, K13
#ISMS-02
★★★★★
ISO/IEC 27001 資訊安全管理系統標準架構與核心
核心概念
掌握 ISO/IEC 27001 作為ISMS 的國際標準，理解其基於風險評估的方法論。標準包含主體條款（規範管理體系的要求，如領導承諾、規劃、支援、運作、績效評估、改進）和附錄 A（Annex A，提供一系列控制措施的參考）。 對應能力：資訊安全管理概論 K09, 資訊安全規劃實務 K01
#ISMS-03
★★★★
ISMS 的PDCA 循環模型
核心概念
理解ISMS 的生命週期和持續改進是透過Plan-Do-Check-Act (PDCA) 模型驅動的：規劃 (建立 ISMS 政策、目標、流程和控制措施)、執行 (實施和運作已規劃的控制措施)、檢查 (監視和評估績效、進行內部稽核和管理審查) 和改進 (根據檢查結果採取矯正措施，持續優化 ISMS)。 對應能力：資訊安全管理概論 K09, K10
#ISMS-04
★★★★★
資訊安全三要素 (CIA)：機密性、完整性、可用性
核心概念
深入理解機密性 (Confidentiality - 確保資訊只被授權者存取)、完整性 (Integrity - 確保資訊的準確性和不被未經授權修改，包括資料和軟體的完整) 和可用性 (Availability - 確保授權者在需要時能存取資訊和資源) 的定義。這三要素是ISMS 保護資訊資產的核心目標。 對應能力：資訊安全管理概論 K09, 資訊安全規劃實務 K01
#ISMS-05
★★★★
資訊安全治理 (Information Security Governance) 在 ISMS 中的角色
核心概念
理解資訊安全治理是確保資訊安全活動與組織整體策略和目標一致、滿足利害關係人需求、並有效管理資安風險和資源的最高層級框架。它涉及高層領導的參與、政策制定、職責分配和績效監控。 對應能力：資訊安全管理概論 K09, K10, 資訊安全規劃實務 K01
#ISMS-06
★★★
ISMS 的範圍與邊界界定
核心概念
理解在建置 ISMS 初期，明確界定適用範圍的重要性。這包括定義組織單位、地點、資產、業務流程、系統和服務等邊界。範圍界定需考量組織的業務需求、風險和合規義務。 對應能力：資訊安全管理概論 K09, 資訊安全規劃實務 K01
#ISMS-07

資訊安全政策與其要素
核心概念
理解資訊安全政策是ISMS 的基礎文件，由高層管理核准，概述組織對資訊安全的總體方向與承諾。政策應清晰、簡潔，並傳達給所有相關人員。其中應包含資安目標和基本原則。 對應能力：資訊安全管理概論 K09, K10, 資訊安全規劃實務 K01
#ISMS-08

資訊安全組織結構與職責分配
核心概念
了解在ISMS 中建立明確的組織結構和分配資訊安全職責的重要性，包括指定資安主管/委員會、定義各部門和個人的資安責任。這有助於確保資安活動得到適當的管理和執行。 對應能力：資訊安全管理概論 K10, 資訊安全規劃實務 K01
#ISMS-09
★★★★
資訊資產的識別、分類與清單
核心概念
掌握識別組織的所有資訊資產（硬體、軟體、資料、服務、人員、文件等）是ISMS 的基礎工作。理解根據其重要性、敏感度和價值對資產進行分類，並建立和維護最新的資產清單的重要性。資產清單是風險評估和控制措施實施的關鍵輸入。 對應能力：資訊安全管理概論 K04, K11, 資訊安全規劃實務 K04
#ISMS-10
★★★★★
資訊安全風險評估流程
核心概念
掌握ISMS 風險評估的標準流程：識別風險（包括識別資產、威脅和弱點），分析風險（評估威脅發生的可能性和弱點被利用後的影響），以及評估風險（根據分析結果確定風險等級，通常使用風險矩陣）。理解風險評估是ISMS 的核心，驅動後續的風險處理。 對應能力：資訊安全管理概論 K04, K11, 資訊安全規劃實務 K03, K11, L12301
#ISMS-11
★★★★
風險分析的考量因素
核心概念
理解在進行風險分析時需要考慮的各種因素，包括資訊資產的價值、威脅的特性（如攻擊者能力、動機）、弱點的嚴重性、以及現有控制措施的有效性。分析結果需結合組織的風險準則來評估風險等級。 對應能力：資訊安全管理概論 K04, K11, 資訊安全規劃實務 K03, K11
#ISMS-12
★★★★★
資訊安全風險處理流程與選項
核心概念
掌握風險處理的流程：根據風險評估結果，選擇適當的處理選項，制定風險處理計畫，並實施計劃中的控制措施。理解四種主要處理策略：風險規避 (Risk Avoidance)、風險降低/緩解 (Risk Mitigation)、風險轉移/分擔 (Risk Sharing)、風險接受/保留 (Risk Retention)。通常可同時採用多種策略。 對應能力：資訊安全管理概論 K04, K11, 資訊安全規劃實務 K03, K11, L12301
#ISMS-13
★★★★
風險處理選項的具體應用
核心概念
能針對特定情境，說明如何應用四種風險處理策略。例如：風險規避（不從事某高風險活動、停止某服務）；風險降低（實施控制措施如加密、多因子驗證、教育訓練、弱點修補）；風險轉移（購買網路保險、外包給專業服務商）；風險接受（成本過高或影響極低時，有意識地接受經高層核准）。 對應能力：資訊安全管理概論 K04, K11, 資訊安全規劃實務 K03, K11, L12301
#ISMS-14
★★★★
殘餘風險與風險接受
核心概念
理解殘餘風險是實施風險處理措施後仍存在的風險。對於不可接受的殘餘風險，需要進一步採取處理措施或尋求更高層級的風險接受核准。理解對所有殘餘風險都應進行文件化記錄，並納入持續監控和審查。 對應能力：資訊安全管理概論 K04, K11, 資訊安全規劃實務 K03
#ISMS-15
★★★
適用性聲明 (Statement of Applicability, SoA) 的目的與內容
核心概念
理解 SoA 是 ISMS 的重要文件，用於證明組織已根據風險評估結果選擇和實施了適當的控制措施。它應列出所有已納入 ISMS 範圍並已實施的控制措施，說明實施原因，並說明為何排除 ISO/IEC 27002 附錄 A 中未實施的控制措施。 對應能力：資訊安全管理概論 K09, 資訊安全規劃實務 K01
#ISMS-16
★★★★
資訊安全目標的設定與衡量
核心概念
理解ISMS 需要設定明確的資訊安全目標，這些目標應與資安政策一致，並能衡量 (SMART 原則 - Specific, Measurable, Achievable, Relevant, Time-bound)。目標的設定應考量風險評估結果和合規要求，並由高層核准。 對應能力：資訊安全管理概論 K09, K10, K15, 資訊安全規劃實務 K01
#ISMS-17
★★★★★
存取控制的基本原則與實施
核心概念
掌握存取控制是保護資訊資產的關鍵防線。理解存取控制的類型（物理、技術、管理）和原則（最小權限、僅知）。了解使用者存取管理流程（帳號建立、權限分配、定期審查、停用/移除）和身分驗證技術（密碼、多因子驗證 - Q1 I21, Q23 I21, Q39 I22）。 對應能力：資訊安全管理概論 K05, K13, K14, 資訊安全規劃實務 K05, K13
#ISMS-18
★★★★
密碼控制措施與最佳實踐
核心概念
理解強密碼策略的要素（複雜度、長度、避免常用詞）。了解密碼儲存的安全性（應雜湊並加鹽，而非明文）。掌握定期更改密碼的要求（雖然趨勢是長密碼+多因子驗證可減少更改頻率）以及處理密碼遺失或洩漏的程序。 對應能力：資訊安全管理概論 K05, K13, 資訊安全規劃實務 K05
#ISMS-19
★★★★★
職務區隔 (Separation of Duties, SoD) 的實施
核心概念
深入理解職務區隔作為管理控制在防止舞弊和錯誤中的作用。能識別需要進行職務區隔的關鍵業務流程（如採購、支付、系統變更）。了解在資源不足無法完全區隔時，可以實施的補償性控制措施（如活動監視、稽核紀錄審查、管理監督 - Q10 I21）。 對應能力：資訊安全管理概論 K10, 資訊安全規劃實務 K01, K10
#ISMS-20
★★★★
物理與環境安全控制
核心概念
理解保護資訊資產所在實體區域的安全控制措施，包括實體門禁控制（如鎖、門禁卡）、周邊安全（如圍牆、監控 - Q4 I21）、設備安全（如防止被盜、破壞）以及環境威脅防護（如火災、水災、電力中斷 - Q36 I21 提到的時間校正與可用性風險）。 對應能力：資訊安全管理概論 K12, K14
#ISMS-21
★★★★★
營運安全管理：變更管理與組態管理
核心概念
掌握變更管理流程：對系統、軟體、硬體、組態等任何變更都應經過正式的評估、核准、實施和審查程序，以降低引入安全風險的可能性（如 Q28 I21 的更新問題）。理解安全組態管理：確保系統按安全基準進行配置，移除不必要功能（如 Q22 I22 關閉驗證功能）。 對應能力：資訊安全管理概論 K14, 資訊安全防護實務 K06
#ISMS-22
★★★★★

核心概念
理解日誌記錄（Logging）是偵測事件、支持調查和取證的關鍵。了解應記錄的關鍵事件類型（如登入失敗、權限變更、系統錯誤 - Q5 I22 情境）。掌握定期審查日誌的重要性（Q4 I21）以及使用安全性資訊與事件管理 (SIEM) 系統進行集中收集、分析和關聯（Q16 I21, Q26 I21, Q28 I21 情境）。 對應能力：資訊安全管理概論 K08, K15, 資訊安全規劃實務 K08, K16, 資訊安全防護實務 K06

#ISMS-27
★★★★
檔案上傳安全控制
核心概念
理解不安全的檔案上傳功能是常見的弱點，可能導致遠端程式執行。掌握相應的防護措施，包括嚴格驗證檔案類型（不只看副檔名）、限制檔案大小、檢查檔案內容（如移除惡意腳本）、將上傳檔案儲存到非 Web 可執行目錄，並設定目錄權限為不可執行（Q3 I22, Q35 I22）。 對應能力：資訊安全防護實務 K07, K08, K09, S15

#ISMS-29
