#ASSEST-01
★★★★★
資訊安全評估的目的與重要性
核心概念
理解資訊安全評估（包括弱點掃描、滲透測試、程式碼分析、資安健診等）是系統性地檢查和測試組織的安全狀態。其主要目的是識別安全弱點、評估控制措施的有效性，並提供改進安全防護的建議。它是風險評估和風險處理的關鍵輸入。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-02
★★★★
不同安全評估方法的區別與適用性
核心概念
理解不同的安全評估方法有不同的側重點和目的。例如，弱點掃描用於廣泛識別已知弱點；滲透測試用於模擬攻擊者實際利用漏洞；程式碼分析用於在開發階段檢查程式碼缺陷；資安健診是一個更全面的體檢。應根據評估目標、預算和範圍選擇適合的方法 (Q20 I22 提及不同測試方法)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-03
★★★
主動與被動安全評估
核心概念
了解安全評估可以分為主動 (Active) 和被動 (Passive) 方式。主動評估（如弱點掃描、滲透測試）直接與目標系統互動以尋找弱點。 被動評估（如日誌分析、配置審查、文件審查）不與目標系統直接互動。 對應能力：資訊安全技術概論 K08, K19
#ASSEST-04
★★★★
安全評估在SSDLC 中的角色
核心概念
理解在安全開發生命週期 (SSDLC) 的各個階段都應融入安全評估活動。例如，設計階段進行威脅建模和架構審查，編碼階段進行程式碼分析 (SAST)，測試階段進行滲透測試 (DAST, Pen Testing) (Q20 I22 提及開發測試階段的安全活動)。 對應能力：資訊安全技術概論 K08, K16, 資訊安全防護實務 K08, S15
#ASSEST-05
★★★★
安全評估結果的利用
核心概念
理解安全評估的結果（如弱點報告）應被用於更新風險登記冊、優先排序弱點修補、實施風險處理措施、改進安全控制措施，並作為管理審查和持續改進的輸入 (Q1 I22, Q17 I21, Q27 I21)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全規劃實務 K03, K11, K19
#ASSEST-06
★★★★★
弱點掃描 (Vulnerability Scan) 的定義與目的
核心概念
掌握弱點掃描是使用自動化工具，對系統、網路、應用程式進行廣泛、快速的檢查，以識別已知安全弱點的過程。其目的是全面了解資產中已知的漏洞，並優先排序修補工作。它是偵測性控制的一種 (Q4 I21, Q1 I22, Q11 I21)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11, S13
#ASSEST-07
★★★★
弱點掃描器的類型與功能
核心概念
了解不同類型的弱點掃描器：網路掃描器（檢查主機、服務、通訊埠）、應用程式掃描器（檢查 Web 應用程式漏洞）、資料庫掃描器等。常見工具如 Nessus (Q17 I21 提及)、OpenVAS。這些工具通常包含大量已知漏洞的簽名庫。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11, S13
#ASSEST-08
★★★★
弱點掃描的限制
核心概念
理解弱點掃描的主要限制：它主要基於已知漏洞資料庫，難以發現零日漏洞、邏輯漏洞或需要多個漏洞組合才能利用的問題 (Q43 PRACTICE)。它不會實際利用漏洞，因此無法評估風險的真實影響。可能會產生誤報 (False Positive)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11, S13
#ASSEST-09
★★★
弱點掃描在弱點管理中的角色
核心概念
弱點掃描是弱點管理流程中風險識別階段的主要工具。掃描結果是後續評估、優先排序和修補工作的基礎 (Q1 I22 提及掃描結果)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-10
★★★★
定期弱點掃描的必要性
核心概念
理解IT 環境是動態變化的（新系統上線、配置變更、新弱點被發現）。因此，弱點掃描應定期進行（如每季一次），並在重大變更後立即進行，以確保弱點被及時發現 (Q1 I22 提及定期掃描, Q17 I21 提及評估時機)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-11
★★★★★
滲透測試 (Penetration Testing) 的定義與目的
核心概念
掌握滲透測試是一種授權的、主動的安全評估方法，透過模擬真實攻擊者的行為和技巧，以識別和驗證實際可被利用的安全弱點，並評估攻擊成功的潛在影響。其目的是深入了解安全防護的有效性 (Q20 I22, Q28 I22, Q38 I22 題組)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11, S15
#ASSEST-12
★★★★
不同滲透測試類型：黑箱、灰箱、白箱
核心概念
了解滲透測試根據測試團隊對目標的了解程度分為不同類型：黑箱測試 (Black Box - 測試者對目標一無所知，模擬外部未知攻擊者)、灰箱測試 (Grey Box - 測試者擁有部分資訊，如使用者帳號或系統架構，模擬內部人員或已知情者)、白箱測試 (White Box - 測試者擁有所有資訊，如原始碼、架構圖，模擬具備內部知識或資源的攻擊者) (Q45 PRACTICE)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-13
★★★★
滲透測試的階段
核心概念
了解滲透測試通常包含多個階段：偵察 (Reconnaissance - 收集目標資訊)、掃描 (Scanning - 發現活動主機、服務、弱點)、漏洞利用 (Exploitation - 實際攻擊利用弱點)、後滲透 (Post-Exploitation - 維持存取、權限提升、橫向移動、數據外洩)、報告。理解攻擊鏈中的階段有助於理解滲透測試的流程 (Q38 VTAM)。 對應能力：資訊安全技術概論 K08, K09, K19, 資訊安全防護實務 K08, S11, S15
#ASSEST-14
★★★★★
滲透測試與弱點掃描的區別
核心概念
掌握弱點掃描是自動化、廣泛、不實際利用，用於識別已知弱點清單。而滲透測試是手動或半自動化、有針對性、實際利用漏洞，用於驗證漏洞、評估實際風險和防護有效性。兩者相輔相成。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-15
★★★★
滲透測試中的漏洞利用
核心概念
在滲透測試的漏洞利用階段，測試者使用特定的漏洞利用工具 (Exploit) 或技術來證明發現的弱點是可被實際攻擊的 (Q37 VTAM)。這一步驟是滲透測試與弱點掃描的主要區別之一。 對應能力：資訊安全技術概論 K08, K09, K19, 資訊安全防護實務 K08, S15
#ASSEST-16
★★★★★
滲透測試中的權限提升與持久化
核心概念
在滲透測試的後滲透階段，測試者會嘗試權限提升 (Privilege Escalation)，以獲取對系統的更高控制權 (Q39 I22, Q39 VTAM)。他們也會嘗試建立持久化 (Persistence) 機制，以維持對系統的長期存取，模擬攻擊者的真實行為 (Q36 I22, Q40 VTAM)。 對應能力：資訊安全技術概論 K08, K09, K19, 資訊安全防護實務 K08, S15
#ASSEST-17
★★★★
滲透測試中的橫向移動與目標達成
核心概念
在滲透測試中，測試者在獲取一個系統的控制權後，會嘗試在內部網路中進行橫向移動 (Lateral Movement - Q41 VTAM)，尋找並存取其他高價值目標或數據。最終目標是證明攻擊者能達到特定目標，如數據外洩或服務中斷。 對應能力：資訊安全技術概論 K08, K09, K19
#ASSEST-18
★★★
滲透測試常用工具與框架
核心概念
了解滲透測試團隊常用的工具和框架，如 Metasploit (漏洞利用框架)、Nmap (網路掃描)、Burp Suite (Web 應用測試)、Wireshark (網路封包分析)、Kali Linux (預裝許多工具的作業系統)。 對應能力：資訊安全技術概論 K08, K09, K19, 資訊安全防護實務 S10
#ASSEST-19
★★★★
滲透測試報告
核心概念
滲透測試的最終輸出是詳細的測試報告。報告應包含測試範圍、方法、發現的所有漏洞（包括如何利用、影響）、風險評估、以及詳細的修補建議。報告應清晰、準確，並提供技術和管理層都能理解的資訊 (Q59 SECARCH)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-20
★★★★★
程式碼安全測試的目的
核心概念
理解程式碼安全測試旨在在軟體開發階段或之後，檢查應用程式的原始碼或運行行為，以識別和定位程式碼中的安全缺陷 (弱點)。這比在部署後發現問題成本更低。 對應能力：資訊安全技術概論 K08, K16, 資訊安全防護實務 K08, S15
#ASSEST-21
★★★★★
靜態應用安全測試 (SAST)
核心概念
靜態應用安全測試 (Static Application Security Testing, SAST) 是一種不運行程式碼，透過分析原始碼或二進位碼來尋找已知安全漏洞或編碼標準違規的白箱測試方法。它通常在開發早期集成到開發流程中 (Q20 I22, Q28 I22, Q29 I22, Q53 ACDOSOD)。 對應能力：資訊安全技術概論 K08, K16, 資訊安全防護實務 K08, S15
#ASSEST-22
★★★★★
動態應用安全測試 (DAST)
核心概念
動態應用安全測試 (Dynamic Application Security Testing, DAST) 是一種在應用程式運行時，從外部發送惡意輸入並觀察其響應來尋找安全漏洞的黑箱測試方法。它可以發現運行時的問題，如注入漏洞、跨站腳本 (Q20 I22, Q46 PRACTICE)。 對應能力：資訊安全技術概論 K08, K16, 資訊安全防護實務 K08, S15
#ASSEST-23
★★★★
SAST 與DAST 的區別與結合
核心概念
理解SAST 在開發早期發現程式碼本身的弱點，但難以發現配置問題或運行時邏輯錯誤。DAST 在運行時發現問題，但無法精確定位到原始碼中的漏洞位置。兩者相輔相成，結合使用能提供更全面的應用安全測試。 對應能力：資訊安全技術概論 K08, K16, 資訊安全防護實務 K08, S15
#ASSEST-24
★★★★
使用程式碼分析工具
核心概念
了解用於程式碼安全測試的自動化工具，如商業的 Fortify (Q17 I21 提及)、Checkmarx，開源的 SonarQube 等。SAST 工具分析原始碼，DAST 工具測試運行中的應用程式。這些工具能自動識別常見漏洞模式，提高效率。 對應能力：資訊安全技術概論 K08, K16, 資訊安全防護實務 K08, S15
#ASSEST-25
★★★
第三方軟體元件安全測試
核心概念
理解組織使用的第三方軟體元件（如開源庫、商業組件）可能包含已知漏洞 (Q37 I22 提及清查)。需要對這些元件進行安全測試或檢查已知的漏洞資料庫 (CVE/NVD)，以識別風險。使用軟體物料清單 (SBOM) 有助於此 (Q40 I22, Q20 I22)。 對應能力：資訊安全技術概論 K08, K16, K17, 資訊安全防護實務 K08, S11, S13
#ASSEST-26
★★★★
資安健診 (Security Health Check) 的定義與目的
核心概念
理解資安健診是一個廣泛的安全評估，類似於對組織資安狀態進行「體檢」。它通常涵蓋多個安全領域（如網路、系統、應用、政策、流程），旨在全面了解組織的安全態勢，識別潛在風險和不足 (Q17 I21 提及資安人員重新檢視與評估)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-27
★★★★
資安健診通常包含的評估項目
核心概念
了解資安健診的評估項目通常包括：弱點掃描、安全配置審查、安全政策與程序審查、實體安全檢查、人員訪談、合規性檢查。它通常不會進行實際的漏洞利用（與滲透測試不同）。 對應能力：資訊安全技術概論 K08, K19, 資訊安全管理概論 K09, K10, K12, K13, K14, K17
#ASSEST-28
★★★
資安健診的執行時機
核心概念
資安健診應定期進行，例如每年一次，以持續了解組織的安全狀態。此外，在發生重大安全事件後、引入新系統或技術後、組織發生重大變動（如併購）後，也應考慮進行資安健診。這與風險評估的時機相似 (Q17 I21)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全管理概論 K04, K09, K11
#ASSEST-29
★★★★
第三方機構進行資安健診
核心概念
委託獨立的第三方機構進行資安健診可以提供客觀的評估，並具備更廣泛的專業知識和經驗。這也是滿足某些法規或合約要求的方式 (Q7 I21 提及第三方測試)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全管理概論 K17
#ASSEST-30
★★★★★
安全評估結果與弱點管理
核心概念
理解弱點掃描、滲透測試、程式碼分析、資安健診等安全評估活動的核心輸出是發現的弱點。這些弱點需要被納入弱點管理流程 (識別、評估、修補、監控) (Q1 I22, Q46 ACDOSOD)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11

並非所有弱點都需要立即修補。應根據風險評估的結果，特別是弱點的嚴重性、可利用性以及受影響資產的重要性，對發現的弱點進行優先排序 (Q1 I22, Q17 I22, Q47 PRACTICE)。高風險弱點應優先處理。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11
#ASSEST-32
★★★★

核心概念
安全評估發現的弱點和漏洞利用證據是風險評估（特別是可能性和影響）的重要輸入。評估結果應更新風險登記冊，並驅動風險處理決策 (Q27 I21, Q30 ASSEST)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全規劃實務 K03, K11
#ASSEST-33
★★★★★
驗證弱點修補的有效性
核心概念
在修補弱點後，需要重新進行掃描或測試，以驗證修補是否成功且有效，並且沒有引入新的問題。這通常透過弱點掃描複測 (Rescan) 或針對性的滲透測試來完成 (Q17 I21 提及弱點掃描複測)。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11

滲透測試是識別 Web 應用程式中OWASP Top 10 弱點的有效方法。例如，透過構造惡意輸入測試是否能利用注入漏洞、嘗試未經授權的頁面存取測試失效的存取控制、或檢查預設配置測試安全配置錯誤 (Q32 I22 提及 OWASP Top 25)。 對應能力：資訊安全技術概論 K08, K09, 資訊安全防護實務 K08, S11, S15
#ASSEST-35
★★★★★
如何測試SQL Injection 漏洞
核心概念
測試SQL Injection 漏洞涉及在應用程式的輸入欄位（如登入頁面、搜索欄）注入惡意 SQL 語法（如 `' or '1'='1` --`, `' OR 1=1 /*` -- Q38 I22 提及測試語法），觀察應用程式或資料庫的響應是否異常，以判斷漏洞是否存在 (Q16 I21, Q38 I22 題組情境)。 對應能力：資訊安全技術概論 K08, K09, 資訊安全防護實務 K08, S11, S15

如何測試檔案上傳弱點
核心概念
測試檔案上傳弱點涉及嘗試上傳包含惡意程式碼但偽裝成合法檔案類型（如圖片、txt）的文件，或嘗試上傳到Web 可執行目錄。如果伺服器未對檔案類型、內容或儲存位置進行嚴格驗證和限制，則存在弱點 (Q3 I22, Q33 I22 情境, Q35 I22)。 對應能力：資訊安全技術概論 K08, K09, 資訊安全防護實務 K08, S11, S15

如何測試權限提升 (Privilege Escalation)
核心概念
測試權限提升通常在獲取低權限帳號存取權後進行。測試者嘗試利用系統弱點、配置錯誤（如寬鬆的檔案權限、可寫入的系統目錄）或應用程式漏洞來獲取系統管理員或 root 權限 (Q39 I22 情境)。 對應能力：資訊安全技術概論 K08, K09, 資訊安全防護實務 K08, S11, S15

★★★★
如何測試持久化 (Persistence)
核心概念
測試持久化通常在獲取系統控制權後進行。測試者嘗試使用作業系統的排程功能（如 crontab）、啟動項、使用者配置文件 (.~/.bashrc)、服務等方式，植入後門或反向連接命令，然後重啟系統或等待觸發，檢查是否能維持存取 (Q36 I22 案例)。 對應能力：資訊安全技術概論 K08, K09, 資訊安全防護實務 K08, S15

如何測試DLL Side-Loading 漏洞
核心概念

核心概念

安全評估報告的內容
核心概念
安全評估的最終輸出是詳細的報告。報告應包含評估概述、範圍、方法、發現的所有弱點（包括弱點描述、嚴重性、影響、可利用性）、風險評估、以及詳細的修補或緩解建議 (Q19 ASSEST)。報告應有技術細節供工程師參考，也有非技術總結供管理層閱讀。 對應能力：資訊安全技術概論 K08, K19, 資訊安全防護實務 K08, S11

核心概念
紅隊演練是一種更全面、更真實的安全評估，模擬具有真實攻擊者能力和戰術的團隊，在不被藍隊（防禦團隊）發現的情況下，嘗試達成特定的預設目標。這有助於測試組織的整體防禦、偵測和應變能力 (Q33 I22 情境提到紅隊演練)。 對應能力：資訊安全技術概論 K08, K19
