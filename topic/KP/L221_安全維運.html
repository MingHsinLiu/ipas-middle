安全維運 (Security Operations, SecOps) 的定義與目的
核心概念
理解安全維運是指組織執行日常資安任務和流程的職能，旨在保護資訊資產、持續監控安全狀態、偵測並應對安全事件。其主要目的是維持組織的資安防護水平，確保控制措施有效運作。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K19
#SECOPS-02
★★★★
安全維運與資訊安全管理系統 (ISMS) 的關係
核心概念
理解安全維運是ISMS PDCA 循環中「執行 (Do)」和部分「檢查 (Check)」階段的具體實踐。ISMS 提供高層次的策略和要求，而安全維運則負責執行這些策略和要求中涉及日常運營的部分（如監控、事件處理、漏洞管理） (Q28 I21 提及 SecOps)。 對應能力：資訊安全管理概論 K09, K19, 資訊安全防護實務 K19
#SECOPS-03
★★★
安全維運中心 (SOC) 的角色
核心概念
理解安全維運中心 (Security Operations Center, SOC) 是組織內部或外部負責安全維運職能的團隊或部門。它是一個集中化的單位，負責持續監控、分析、偵測和應對安全事件。擁有專業的資安分析師和工程師 (Q25 I21 提及 SOC 任務)。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08, K19

安全維運的關鍵流程
核心概念
了解安全維運涵蓋的關鍵流程，包括監控與日誌管理、事件應變管理、漏洞管理、威脅情資管理、安全配置管理、惡意程式防護。這些流程需要協同工作以維持整體的防護狀態。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K19

安全維運與 IT 維運的關係
核心概念
理解安全維運與IT 維運 (IT Operations) 需要緊密協作。雖然職責不同，但許多活動（如系統維護、變更管理、補丁管理）需要結合安全考量。有效的安全維運需要建立安全與 IT 團隊之間的溝通與協作機制。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08, K14
#SECOPS-06
★★★★★
日誌記錄 (Logging) 的重要性與來源
核心概念
掌握日誌記錄是安全維運中最重要的活動之一，用於記錄系統和使用者活動、安全事件。重要日誌來源包括作業系統日誌、應用程式日誌、網路設備日誌（如防火牆、路由器）、安全工具日誌（IDS/IPS、AV）等 (Q5 I22 情境中的 auth.log, Q22 I21 提及日誌管理)。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08, K15
#SECOPS-07
★★★★★
安全日誌的集中收集與管理
核心概念
理解從分散的系統中集中收集日誌對於有效分析和關聯事件至關重要。常用技術包括使用日誌收集代理或協議（如 Syslog, Windows Event Forwarding, SNMP - Q16 I21 提及）。SIEM 系統是集中日誌管理和分析的核心平台 (Q26 I21)。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08, K15
#SECOPS-08
★★★★★
安全日誌的分析與關聯
核心概念
理解日誌分析是從大量日誌數據中識別異常模式或安全事件的過程。這通常透過規則（如特定事件序列）、簽名比對或行為分析 (User and Entity Behavior Analytics, UEBA) 進行。將來自不同來源的日誌關聯起來，可以發現更複雜的攻擊 (Q26 I21 提及 SIEM 的關聯分析)。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08, K15
#SECOPS-09
★★★★
安全日誌的保護與保留
核心概念
理解保護安全日誌不被篡改或刪除對於事件調查和取證至關重要 (Q5 I22 情境中的日誌)。需要實施嚴格的存取控制、完整性檢查（如雜湊）以及定期備份。同時，應根據法規要求或組織策略確定日誌的保留期限。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K12, K13
#SECOPS-10
★★★
即時監控
核心概念
即時監控旨在在事件發生時或接近發生時立即偵測到並發出警報。這需要自動化的監控工具和快速響應機制。是縮短偵測時間的關鍵。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08, K15
#SECOPS-11
★★★★★
從監控數據中偵測異常
核心概念
理解偵測異常活動是威脅偵測的核心。這可以透過基於規則（例如，異常時間的登入）或基於行為分析（例如，與用戶基準行為不符的數據存取模式）來實現。SIEM 和 UEBA 工具用於自動化此過程。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08, K15
#SECOPS-12
★★★★★
入侵偵測系統 (IDS) 的作用
核心概念
入侵偵測系統 (Intrusion Detection System, IDS) 監控網路或系統，偵測潛在的攻擊或未經授權的活動。它可以是基於簽名（比對已知攻擊模式）或基於異常（偵測與正常行為的偏差）。IDS 僅發出告警，是重要的偵測控制 (Q4 I21, Q17 PRACTICE)。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K15, 資訊安全規劃實務 K08
#SECOPS-13
★★★★
誘餌系統 (Honeypot) 與威脅偵測
核心概念
部署誘餌系統是偵測攻擊者的一種策略。由於誘餌系統本身不應有合法流量，任何對其的存取嘗試都可能是惡意的，因此能觸發高信度的警報 (Q23 I22, Q52 ACDOSOD)。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K15, 資訊安全規劃實務 K08

威脅獵捕 (Threat Hunting) 的實踐
核心概念
威脅獵捕是主動且疊代地尋找環境中未被現有安全工具偵測到的威脅的過程。它通常基於分析師的假設或威脅情資，利用日誌分析、行為分析、數據探索等技術。是提升偵測能力的重要實踐 (Q9 I22, Q21 PRACTICE, Q51 VTAM)。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K15

利用威脅情資進行威脅偵測
核心概念
將威脅情資 (Threat Intelligence) 整合到安全運營中，例如在 SIEM 中使用已知的惡意 IP、域名、檔案雜湊等來增強偵測規則，可以更有效地識別已知的威脅活動。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K15, 資訊安全規劃實務 K08

弱點管理 (Vulnerability Management) 流程
核心概念
掌握弱點管理是安全維運的核心職能，其標準流程包括識別（掃描/測試）、評估（分析風險）、處理（修補/緩解）和報告/監控。理解這是一個持續不斷的過程 (Q1 I22, Q46 ACDOSOD)。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K08, S11
#SECOPS-17
★★★★★
弱點的優先排序與風險評估
核心概念
理解弱點掃描通常會發現大量弱點，需要根據其風險等級來優先處理。風險等級應基於弱點的嚴重性（如 CVSS 分數 - Q53 VTAM）、可利用性以及受影響資產的重要性（其影響評等） (Q1 I22, Q17 I22, Q47 PRACTICE)。並非所有弱點都需要立即修補。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K08, S11
#SECOPS-18
★★★★★
補丁管理 (Patch Management)
核心概念
補丁管理是弱點處理最重要的方式，它是獲取、測試和部署軟體或韌體更新（補丁）的過程，以修復已知弱點。需要定期檢查更新，規劃測試和部署時程，並追蹤修補狀態。不及時補丁是常見的攻擊媒介 (Q1 I22, Q2 I22, Q28 I21 提及更新管理)。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K08, S11
#SECOPS-19
★★★★
第三方軟體弱點管理
核心概念
管理組織使用的第三方軟體元件（包括開源和商業軟體）的弱點是軟體供應鏈安全的關鍵部分。需要盤點使用的元件、清查已知弱點 (CVE/NVD)、持續監控新的弱點情資，並與供應商協調修補 (Q37-40 I22 題組, Q55 ACDOSOD)。軟體物料清單 (SBOM) 有助於此 (Q40 I22)。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K08, S11
#SECOPS-20
★★★★
配置管理與配置審查
核心概念
確保系統、應用程式、網路設備按照安全基準進行配置，並定期進行配置審查，識別和修復配置錯誤，是降低風險的重要安全維運活動 (Q21 I21, Q42 ACDOSOD, Q58 SECARCH)。不安全的配置是常見的弱點。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K06, K07

系統硬化 (System Hardening)
核心概念
系統硬化是透過關閉不必要的服務、應用程式或功能，移除預設帳戶或憑證，限制權限等方式，減少系統的攻擊面。這是安全配置管理和弱點降低的重要步驟。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K06
#SECOPS-22

惡意軟體 (Malware) 的防護
核心概念
惡意軟體防護是安全維運的基本職能。措施包括部署防毒/反惡意軟體、定期更新病毒碼、執行掃描、電子郵件和網路流量過濾、以及使用者意識訓練。目標是預防、偵測和移除惡意軟體。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K15, 資訊安全防護實務 K06

Endpoint Protection Platform (EPP)
核心概念
EPP 是部署在終端設備（工作站、伺服器）上的安全軟體平台，提供防毒、防惡意軟體、防火牆、入侵防禦等綜合性保護功能。它是預防和偵測惡意程式以及其他終端威脅的主要工具。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K06
#SECOPS-24

Endpoint Detection and Response (EDR)
核心概念
EDR 是一種部署在終端設備上的進階偵測和應變工具。它持續收集終端活動數據（檔案、進程、網路連線等），進行分析，以偵測複雜的威脅 (APT, 零日攻擊)。EDR 提供威脅獵捕和事件調查能力 (Q5 I22 情境中的 EDR 告警)。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K06

沙箱 (Sandbox) 與惡意軟體分析
核心概念
沙箱是隔離的環境，用於安全地執行可疑檔案或程式，觀察其行為以判斷是否為惡意軟體。這是惡意軟體分析和威脅偵測的重要技術，特別是對於未知或變種的惡意軟體 (Q33 I22 情境中的檔案分析)。 對應能力：資訊安全技術概論 K19

電子郵件安全過濾
核心概念
實施電子郵件安全閘道或過濾服務，檢查入站和出站電子郵件，偵測和阻止惡意軟體、釣魚郵件、垃圾郵件或資料外洩嘗試 (Q13 I22 提及 WAF 不用於此)。這是防範社交工程和惡意軟體傳播的主要預防措施。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 K06

數據備份與管理
核心概念
數據備份是安全維運中保護數據可用性的基本且關鍵的活動。需要識別關鍵數據，制定備份策略（頻率、類型）、確保備份的完整性、安全儲存（包括異地備份）以及定期測試備份。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K12
#SECOPS-28
★★★★★
數據復原流程與測試
核心概念
數據復原是從備份恢復數據的過程，是應對數據丟失或損壞事件（如勒索軟體、硬件故障）的關鍵。需要制定明確的復原流程，包括恢復步驟、復原順序等。最重要的實踐是定期測試數據復原，以確保在需要時能成功且快速地恢復數據 (Q26 I21 案例)。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K12
#SECOPS-29
★★★★
資料清除與銷毀
核心概念
在處置包含敏感數據的存儲媒體或設備時，需要安全地清除或銷毀數據，以防止數據洩漏。方法包括數據覆寫、去磁、物理破壞等。應根據數據敏感度和法規要求選擇適當的方法 (Q50 RISKTREAT)。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K12
#SECOPS-30
★★★★

核心概念
對儲存在硬碟、資料庫或雲儲存中的敏感數據進行加密（靜態資料加密），是保護數據機密性的主要控制措施。即使物理媒體丟失或被竊，數據也無法被未授權者讀取 (Q23 I22 提及加密儲存)。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K06, K12, K13

資料洩漏是嚴重的安全事件，需要專門的應對流程。這包括確認洩漏範圍、識別受影響數據和個人、通知受影響者和監管機構（根據個資法等法規 - Q24 I21）、以及分析原因並實施矯正措施。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K08, K10, K12, K17

核心概念
SIEM 是安全運營中心 (SOC) 的核心平台，用於收集、彙整、儲存、分析來自不同安全裝置和系統的大量日誌與事件數據。透過關聯規則和分析，偵測安全事件和攻擊，並提供告警、報告、事件調查功能 (Q16 I21, Q26 I21, Q50 PRACTICE)。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08, K15

資安協作自動化應變 (SOAR)
核心概念
SOAR 平台結合安全編排 (Orchestration)、自動化 (Automation) 和事件應變 (Response) 功能。旨在自動化和協調安全任務和工作流程，例如接收到SIEM 告警後，自動執行威脅情資查詢、資產隔離等步驟，提高應變效率 (Q27 I21, Q51 PRACTICE)。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08
#SECOPS-34

User and Entity Behavior Analytics (UEBA)
核心概念
UEBA 工具分析使用者和實體的行為，建立其正常行為基準，並偵測與該基準偏差的異常行為。這有助於識別內部威脅、帳戶盜用、數據洩漏等難以透過傳統規則偵測的威脅。通常作為 SIEM 的增強功能。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K15

Security Orchestration (SO)
核心概念
安全編排是連接和協調不同安全工具和系統的過程，例如將SIEM 與防火牆、端點安全工具、威脅情資平台等整合，實現自動化的工作流程。它是 SOAR 的一個組成部分 (Q27 I21 提及安全編排)。 對應能力：資訊安全技術概論 K19, 資訊安全規劃實務 K08
#SECOPS-36
★★★★
Security Automation (SA)
核心概念
安全自動化是利用技術自動執行重複性、手動的安全任務，例如漏洞掃描、修補部署、日誌分析、威脅隔離等。自動化能提高效率、減少人為錯誤，並使安全團隊能專注於更複雜的工作。它是 SOAR 的另一個組成部分 (Q27 I21 提及自動化)。 對應能力：資訊安全技術概論 K19, 資訊安全防護實務 S07

NDR 工具監控和分析網路流量，使用機器學習和行為分析來偵測異常或惡意活動。它可以提供網路可見性並幫助識別內部橫向移動、數據外洩等威脅 (Q12 I22 提及)。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K15

核心概念

時間同步 (Time Synchronization) 的重要性
核心概念
理解在所有系統和安全設備上維持準確且同步的時間對於日誌分析、事件關聯和事件調查至關重要。不準確的時間戳會導致日誌難以比對，無法準確判斷事件發生的順序和關聯性 (Q36 I21 提及資料庫伺服器時間校正)。通常使用 NTP (Network Time Protocol) 服務實現。 對應能力：資訊安全技術概論 K19, 資訊安全管理概論 K08, K15
